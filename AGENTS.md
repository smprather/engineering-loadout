## Cold Start

This repository is engineering-loadout: an offline-first, no-root package manager for Linux/Windows compute environments. `./loadout` is a POSIX-sh shim that self-bootstraps the bundled portable Python 3.14 (no system Python required) and execs `loadout_main.py` under it. Driven by `payload/packages.json` (`schema_version: 3`). Prefer changes that preserve RedHat/Alma/RHEL 7/8/9, Suse, WSL, Windows PowerShell, and locked-down corporate machines.

Use `rg` first. Use `sh -n loadout` for the POSIX-sh shim, `python3 -m py_compile loadout_main.py` for the Python installer, and `bash -n envs/bash/global/bashrc` after installer/shell edits. For Neovim config checks in this sandbox, use temporary writable state/cache dirs:

```bash
XDG_CACHE_HOME=/tmp/codex-nvim-cache XDG_STATE_HOME=/tmp/codex-nvim-state nvim --headless +qa
```

## Lessons Learned

- Do not use `xset +fp ~/.local/share/fonts` from shell startup. Even with valid `fonts.dir`, X may reject user-home paths such as `/home/mylesp` when the home directory is `700`. Use fontconfig (`fc-cache`) for modern Linux apps and WSLg.
- Vendored fonts belong in `~/.local/share/fonts`. Generate `fonts.scale`/`fonts.dir` when `mkfontscale`/`mkfontdir` exist, but rely on `fc-cache` for actual desktop app discovery.
- Font archives live under `payload/fonts/`. Archives over normal GitHub size limits should be split as `payload/fonts/Name.zip.part-000`, `Name.zip.part-001`, etc. The installer rejoins split archives under `/tmp` before unzipping. Use 45 MiB chunks to stay below GitHub's 50 MB warning threshold.
- Font installation has a fonts-phase backup separate from the main `loadout_backups` archive: normal installs move an existing `~/.local/share/fonts` aside to `fonts.bak*` before extraction, while `--no-backup` must suppress that move and reuse the directory in place.
- Before each install area writes files, the installer verifies that the target directory is writable. If an area is not writable, it refuses that area with a warning, continues later areas when possible, and ends with an install results table using `yes`, `no`, and `skip`.
- Pre-built Linux binaries live under `payload/<platform>/`, for example `payload/el8.x86_64.glibc2p28/`. `RPATH=$ORIGIN/../lib64:$ORIGIN/../lib` is pre-baked into each binary in the repo before bzip2 compression -- the installer is pure decompress + chmod, no runtime patchelf step. Installer runs `ldd` on installed binaries and warns about missing `.so` dependencies. If a running binary cannot be replaced, installer continues and prints a retry notice.
- **Binary bundling order is critical: strip -> patchelf -> bzip2.** Never strip after patchelf. patchelf reorganizes ELF segments to accommodate the new RPATH string; stripping after patchelf moves `.dynstr` outside a `PT_LOAD` segment and corrupts the binary (symptom: segfault or "undefined symbol" at runtime). `strip-all-elf-binaries` detects patchelf'd payloads via `readelf -d` RPATH check and skips re-stripping them.
- Tcl/Tk 9 shared libraries embed script libraries via zipfs. Do not strip `libtcl9.0.so` or `libtcl9tk9.0.so`; patchelf RPATH only, then bzip2. Strip only the launcher binaries (`tclsh`, `wish`) before patchelf.
- **Go binaries must use compile-time strip flags, not post-build strip.** Build with `go build -ldflags="-w -s"`. Running `strip --strip-all` on a Go binary post-build removes GC maps and stack unwind metadata, causing SIGSEGV. `-w` drops DWARF, `-s` drops the symbol table -- identical effect to strip but safe because Go's linker handles the removal correctly.
- **`./release --dry-run` is the release gate.** It runs independent pre-release gates in parallel: `scan-for-malware`, `tests/prebuilt-binaries`, `build/farm-versions --format tsv`, and `sha256sums.txt` generation. The final release step is skipped for dry-runs and otherwise waits for those gates; malware scan, binary smoke, and checksum generation are mandatory. `scan-for-malware` caches only clean verdicts under `${XDG_CACHE_HOME:-~/.cache}/engineering-loadout/malware-scan-v1/`; the cache key hashes source payload bytes, `scan-for-malware`, YARA binary/rules/tag, scan flags, and ClamAV engine/signature fingerprint, so payload/rule/script/signature changes force a fresh scan. Use `--no-cache` to force a fresh scan and `--clear-cache` to delete cached clean results. `tests/prebuilt-binaries` does a full `./loadout install @shared --dest-dir /tmp/...`, then probes each executable in `<dest>/local/bin` with `PATH=<dest>/local/bin:/usr/bin:/bin:/usr/sbin:/sbin` so wrappers cannot accidentally use tools from the system or `~/.local/bin`. It checks loader failures, signal crashes, editor runtime sentinels, and installed `nvim` headless against the installed runtime. Portable Python intentionally keeps generic `python3`/`pip3` links in `~/.local/bin` so `python3` on PATH resolves to 3.14; the only hard py3.6 holdout is Meld's `bin/meld` launcher, which pins `/usr/bin/python3.6` for PyGObject compatibility.
- **Main deployment smoke:** run `tests/install-split-shared-envs` before commits that affect installer/env/shared-prefix behavior. It installs `@shared` into a temp non-home tree, then installs Bash-only `@envs` into a separate temp HOME with `LOADOUT_CFG_SHARED_PREFIX=<shared>/local`, and smokes Bash startup, shared PATH, terminfo, WezTerm completions, and core tool startup. This is the production deployment shape; do not rely only on single-tree `--dest-dir` tests.
- **Suite entry point:** `tests/run-all` (Tier 1 fast + Tier 2 integration; `--fast` / `--container`). **Stock EL8 is the verification baseline for install behavior; the dev box is not** -- anything touching install behavior, payload paths, or repo layout must pass the Tier 3 container gate before it is trusted.
- **Maximum-coverage Linux smoke (Tier 3):** run `tests/prebuilt-binaries-almalinux8` when Docker is available; `--full` additionally runs doctor, resolver dry-runs, the completion diff, the unit/registry tests, and both integration installs inside the container. It builds a clean `almalinux:8.10` smoke image, bind-mounts this repo read-only, copies it inside the container, bootstraps the repo-bundled Python via `./loadout`, then runs the same `@shared` binary/runtime smoke from that base OS. Expected host-contract skips are explicit: `cloc` needs host Perl, `meld` needs EL8 `/usr/bin/python3.6`, and GL GUI apps need host GLVND/OpenGL dispatcher libs (`libGL.so.1`, etc.).
- **Never bundle glibc components** (`libc.so.6`, `libm.so.6`, `libpthread.so.0`, `libdl.so.2`, `librt.so.1`). They must match the system `ld-linux.so.2` exactly. Bundling them causes `undefined symbol: ..., version GLIBC_PRIVATE` crashes. These are always present on EL8 systems.
- **Never bundle OpenGL dispatcher libs** (`libGL.so.1`, `libGLX.so.0`, `libGLdispatch.so.0`). They must match the host display driver. Mesa vendor/runtime pieces are okay: `mesa3d_libs` ships `libEGL_mesa`, `libgbm`, `libglapi`, DRI drivers, GLVND JSON, and `libLLVM-17`; wrappers must set `LD_LIBRARY_PATH`, `LIBGL_DRIVERS_PATH`, and `__EGL_VENDOR_LIBRARY_DIRS`.
- Use `./strip-all-elf-binaries` (Python 3.14) after adding vendored binaries, libs, parser grammars, or tar archives. It walks the repo outside `.git`, strips raw ELF files in place, strips ELF payloads inside standalone `.bz2`, and rewrites tar archives as `.tar.bz2`. Tar archives are skipped on later runs when their size and modification time still match the strip manifest.
- `./update tldr-data` writes `payload/tldr/tldr-pages.tar.bz2`; installer still accepts legacy `.tar.gz`, replaces any existing tealdeer cache unless `--skip tldr-data` is passed (or `tldr-data` is not in the selected set), and strip normalization will convert tar archives to bzip2.
- Platform runtime archives live under `payload/<platform>/runtime/`. `helix.tar.bz2` installs to `~/.local/share/helix/runtime` with `runtime/tutor` as sentinel. `vim92.tar.bz2` installs to `~/.local/share/vim/vim92` with `filetype.vim` as sentinel. `nvim.tar.bz2` installs to `~/.local/share/nvim/runtime` with `filetype.lua` as sentinel. `st.tar.bz2` installs to `~/.local/share/terminfo/s/` with `st-256color` as sentinel. `mesa3d_libs.tar.bz2` is chunked as `.part-000..002` and installs Mesa under `~/.local/lib64` / `~/.local/lib64/dri`. `wezterm.tar.bz2` is chunked as `.part-000..001` and installs wrappers at `~/.local/bin/wezterm`, `~/.local/bin/wezterm-gui`, and `~/.local/bin/wezterm-mux-server`; real upstream sibling binaries live under `~/.local/lib/wezterm/` so `wezterm start` can exec `wezterm-gui`. WezTerm zsh completion is env-owned at `envs/zsh/site-functions/_wezterm`, not in the app runtime; bash completion remains available from `wezterm shell-completion --shell bash`.
- `vcd-toggle-profiler` is a runtime archive, not a bare bin, because the C++ binary needs uPlot JS/CSS to generate self-contained HTML. Archive layout: `bin/vcd-toggle-profiler` wrapper, `lib/vcd-toggle-profiler/vcd-toggle-profiler.bin`, `share/vcd-toggle-profiler/uplot/`, and licenses. Build with `build/build-vcd-toggle-profiler.sh`; it uses EL8 `/usr/bin/g++` 8.5 and `-lstdc++fs`, not upstream CMake Release (`-march=native`).
- Runtime launchers must derive install prefix from their installed path, not `$HOME`. `--dest-dir` installs can be run with a fake `HOME`, so wrappers like Vim/GVim, Helix, Fish, and Meld must find bundled runtime/data under the staged root. Fish launcher must also ensure `<prefix>/etc/fish` exists before execing `fish.bin`; fish 4.7.1 only switches into relocatable mode when both `<prefix>/share/fish` and `<prefix>/etc/fish` exist, otherwise it overwrites `__fish_*` with its build-time prefix.
- Split `@shared` + `@envs` deployments use `LOADOUT_CFG_SHARED_PREFIX` as the local-root (`<shared>/local`). Shell startup must use it for PATH, TERMINFO_DIRS, Qt plugin path, nvim-qt runtime, and GI typelibs; do not hard-code those to `$HOME/.local`.
- Bundled terminfo belongs under `<prefix>/share/terminfo`, not `~/.terminfo`. `envs/bash/global/bashrc` prepends `$HOME/.local/share/terminfo` to `TERMINFO_DIRS` so ncurses finds staged/shared installs of `st-256color` and any future shipped terminfo entries.
- Tmux double-click word selection is controlled by `envs/tmux/tmux-word-separators`, because tmux `word-separators` is a literal character list and cannot express a Unicode emoji class. Keep the helper installed with `envs/tmux/tmux.conf` so Starship prompt emoji such as the read-only lock are treated as separators.
- WSL Windows Terminal does not read WSL fontconfig. Fonts must also be installed on the Windows side for Windows Terminal UI selection.
- Windows installs should prefer `.\loadout.cmd` (or `pwsh -NoProfile -ExecutionPolicy Bypass -File .\loadout.ps1`) because running `loadout.ps1` directly from a WSL UNC path can be blocked as an unsigned remote script before repo code starts. `loadout.cmd` uses `%USERPROFILE%\.local\opt\powershell\7\pwsh.exe` when present, otherwise system `pwsh.exe`, otherwise Windows PowerShell 5.1 runs `loadout-pwsh-bootstrap.ps1` to extract the bundled `payload/windows.x86_64/powershell/PowerShell-*-win-x64.zip[.part-NNN]` without winget/admin and then re-run the installer. `loadout.ps1` also writes a Windows Terminal fragment at `%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\engineering-loadout\powershell.json`.
- Do not backup font files during main pre-install backups; vendored Nerd Font archives are large. Backup uses Python recursive copy with font-extension excludes, not host `rsync`.
- Env installs must not follow old config symlinks back into the repo. `sync_dir` removes a symlinked destination directory before copying, refuses overlapping source/destination trees, and tolerates source entries that vanish during copy. This prevents stale links such as `~/.config/nvim/lsp -> ~/dotfiles/nvim/lsp` from letting `loadout install @envs` mutate the repository.
- Bash aliases are expanded while parsing sourced files in interactive shells. Before defining a function whose name may already be an alias (`df`, `grep`, `cat`, etc.), `unalias name 2>/dev/null || true` first; otherwise a later `exec bash` can fail with `syntax error near unexpected token '('` even when `bash -n` passes.
- `Snacks.nvim` provides the no-argument Neovim dashboard. Its dashboard buffer has filetype `snacks_dashboard`.
- `mini.trailspace` highlights trailing whitespace via window-local matches. Disabling only by filetype can race with dashboard rendering. For Snacks dashboard, set `vim.b.minitrailspace_disable = true`, `list = false`, and delete existing `MiniTrailspace` matches on dashboard open/update.
- Fresh Neovim config must start on locked-down machines. If `lazy.nvim` is missing and `git` cannot clone it, `envs/nvim/init.lua` disables the plugin layer cleanly (`vim.g.loadout_plugins_enabled = false`) instead of erroring.
- Tree-sitter offline support targets Neovim v0.12+ only. Vendored `nvim-treesitter` and `treesitter-parser-registry` live under `payload/treesitter/vendor/`; prebuilt parsers, parser-info, queries, and registry cache live under `payload/treesitter/prebuilt/<platform>/`, where platform is `$(uname -s lower)-$(uname -m)-<glibc|musl>`. Build all supported parsers with `./build/treesitter/build_parsers`; it stores parsers as `parser/*.so.bz2`. Installer copies vendor plugins to `~/.local/share/nvim/loadout/vendor/`, decompresses matching parser artifacts to installed `parser/*.so`, and copies metadata directories to `~/.local/share/nvim/tree-sitter-parsers/`.
- `tests/install-linux-tmp-home` simulates a fresh Linux user by running the real installer with a temp `HOME`, temp XDG cache/state dirs, test `--post-install-hook` scripts, and `--skip @fonts-all`, then smoke-tests offline Tree-sitter with headless Neovim. It explicitly selects `@envs-all` alongside `@engineering-loadout` so the test still covers optional editor/shell config while normal `@envs` remains Bash-only.
- `.codex/` is local ignored Codex state, not repo-managed configuration.
- Corp/site/user add-ons can be invoked explicitly with `./loadout install ... --post-install-hook <script>`. Multiple hooks are allowed and run in argument order. Hooks are executed directly, so each must be executable and provide its own shebang or binary format. Hooks run after global install steps, before automatic layer `install.sh` scripts, with `LOADOUT_*` environment variables: `LOADOUT_REPO`, `LOADOUT_HOME`, `LOADOUT_BACKUP_DIR`, `LOADOUT_DEST_DIR`, `LOADOUT_NO_BACKUP`. Skip fonts or the tldr cache via `--skip @fonts-all` / `--skip tldr-data` selectors.
- Linux installer manages Starship at `~/.config/starship/starship.toml` from `envs/starship/starship.linux.toml` and `envs/starship/config-schema.json`; Windows uses `envs/starship/starship.windows.toml`.
- Linux installer entry point is `./loadout` (POSIX-sh shim) which bootstraps Python 3.14 from the bundled portable-python archive and execs `loadout_main.py` (Python 3.14+). Resolves the repo from the script path; must work when invoked from outside the repo root. `tests/install-linux-tmp-home` runs it from `/tmp` to catch regressions.
- Bash startup converges `~/.bashrc`, `~/.bash_profile`, `~/.bash_login`, and `~/.profile` onto `~/.config/bash/bashrc`. Keep the non-exported `LOADOUT_BASHRC_SOURCED` guard so accidental double-sourcing in one shell returns immediately without blocking exec into a preferred bash. If `HOME` is already set (for example `env -i HOME=/tmp/stage bash -lc ...` in `--dest-dir` smoke tests), preserve it instead of resetting from `/etc/passwd`.
- **The prompt block in `envs/bash/global/bashrc` is clobber-sensitive -- do not "simplify" it back to owning `PROMPT_COMMAND`.** The loadout does NOT own `PROMPT_COMMAND`, and Starship does NOT always hook via `PROMPT_COMMAND`. A preexec framework can already be live when our `bashrc` runs: login shells read `/etc/profile.d/wezterm.sh` (and `vte.sh`), which load **bash-preexec** and register `precmd_functions` + a `PROMPT_COMMAND` install stub *before* our `bashrc`. Two consequences a future edit must respect: (1) our clean-slate `unset -f $(declare -F ...)` deletes those framework functions, leaving dangling references (`PROMPT_COMMAND` -> missing `__bp_install` spams "command not found"; `precmd_functions` -> missing `__wezterm_*`); (2) `starship init bash` auto-detects `precmd_functions` and registers `starship_precmd` into the **array**, leaving `PROMPT_COMMAND` untouched. The old code's `unset PROMPT_COMMAND` + `export PROMPT_COMMAND="/bin/stty '$(stty -g)';$PROMPT_COMMAND"` then wiped the framework's driver, so `starship_precmd` (and everything in `precmd_functions`) never fired -- **symptom: no Starship prompt on the first login shell, but fine after `exec bash`** (a non-login shell that never sourced `/etc/profile`, so no framework, so Starship falls back to `PROMPT_COMMAND`). The required order, do not reorder: reset framework state (`unset precmd_functions preexec_functions __bp_imported bash_preexec_imported PROMPT_COMMAND`) -> source the loadout-owned `wezterm.sh` (gives wezterm users semantic zones / OSC7 even without tmux) -> run `starship init` and let it self-hook (NEVER `unset`/overwrite `PROMPT_COMMAND` around it) -> register echo-restore via `loadout_add_precmd loadout_restore_echo` (array when a framework is live, else `PROMPT_COMMAND`). The deprecated `stty '$(stty -g)'` snapshot is gone on purpose -- it swallowed type-ahead Enter; `loadout_restore_echo` is the no-fork replacement. **Verify with a real PTY** (`tmux new-session ... ; send-keys`), never `bash -lic`: `-c` runs a command list with no prompt cycle, so `precmd_functions` never fire and the bug hides. Always test BOTH a login shell and `exec bash`. Full rationale in `envs/bash/global/README.md` ("Prompt & shell integration") and `docs/BASH.md`.
- **WezTerm shell integration is loadout-owned and vendored, never from `/etc`.** `envs/bash/global/wezterm/wezterm.sh` (see its `PROVENANCE`) is the canonical copy; the bundled wezterm runtime archive ships only the binaries + `wezterm shell-completion` (tab-completion), NOT the integration script. `loadout_find_wezterm_shell_integration` (in `envs/bash/functions.sh`) resolves it: explicit `LOADOUT_CFG_WEZTERM_SHELL_INTEGRATION` -> vendored copy -> paths relative to the installed `wezterm` binary -> `${LOADOUT_CFG_SHARED_PREFIX:-$HOME/.local}`. It deliberately never returns `/etc/profile.d/wezterm.sh` (non-user-writable, distro-package dependent). On by default (`LOADOUT_CFG_ENABLE_WEZTERM_SHELL_INTEGRATION=1`); the script self-skips `dumb`/`linux` terminals and non-interactive shells. tmux-in-wezterm needs `set -g allow-passthrough on` for the OSC to reach wezterm. Outside real WezTerm (`TERM_PROGRAM != WezTerm` and no `WEZTERM_PANE`), `bashrc` must keep the vendored bash-preexec driver but set `WEZTERM_SHELL_SKIP_SEMANTIC_ZONES=1`, `WEZTERM_SHELL_SKIP_USER_VARS=1`, and `WEZTERM_SHELL_SKIP_CWD=1` while sourcing it; otherwise GNOME Terminal/tmux can print raw OSC escapes, and the loadout's PATH-visible `wezterm` wrapper can make prompts block in `wezterm set-working-directory`.
- Package registry (`payload/packages.json`, `schema_version: 3`): every installable thing has a named entry with `kind` (`bin`/`lib-bundle`/`runtime`/`typelib`/`python-base`/`python-tool`/`env`/`font`/`data`/`group`), `platforms: [...]`, and per-kind artifact fields. Packages can declare hard `depends` and soft `recommends`. Groups (keys starting with `@`) bundle related packages and expand recursively with cycle detection. Synthetic groups: `@shared` (every non-env, non-optional package), `@shared-all` (same plus optionals), `@envs` (Bash config only), and `@envs-all` (every env config bundle); `all` is rejected because its historic semantics were misleading. There is no "default install" -- users always name packages or groups explicitly (dnf/apt style). Resolver: `expand_groups` -> `walk_depends` (raise on skip-set conflict unless `--no-deps`/`--force`) -> `walk_recommends` (silent drop) -> `filter_by_platform`. CLI verbs: `install`, `reinstall`, `upgrade`/`update`, `list [--groups|--tag T]`, `search PATTERN`, `info`/`describe`, `resolve`, `doctor`, `snapshot {create|restore|list}`, `clean`; selection uses positional PKG args plus `--skip` / `--no-deps` / `--force`, and install-like verbs also accept `--dry-run`. Bare `install` (no positional args) errors with non-zero exit.
- `uv_extras` on a `python-tool` turns the installer requirement from `uv_tool` into `uv_tool[extra,...]`; every selected extra needs its complete locked offline wheel closure. `parity-plot` is non-optional, pinned to stable upstream tag `v0.7.0`, and rebuilds with `build/build-parity-plot.sh --tag v0.7.0`. It carries **no loadout patch**: through v0.6.0 we patched plotly's CDN reference into an inlined copy, and v0.7.0 does that natively (`[output].plotlyjs` defaults to `inline` for a standalone document). Do not reintroduce the patch, and do not let the inlined default regress -- CDN-backed HTML fails offline, and `tests/install-parity-plot` is what now enforces it by asserting the output embeds plotly and references no CDN. NiceGUI is a core upstream dependency, not a `uv_extras` entry. Static PNG/SVG/PDF export still needs host Chrome/Chromium for Kaleido; loadout does not ship or download a browser.
- `openssh` exists for EL8 `ssh-keygen -Y sign` and an explicit `ssh10` client only. Never ship bare `ssh`, `scp`, or `sftp` from loadout: mainline OpenSSH 10.x rejects Red Hat crypto-policy's `GSSAPIKexAlgorithms` while host `/usr/bin/ssh` accepts it. The package owns `ssh10`, `ssh10.bin`, `ssh-keygen`, `ssh-add`, `ssh-agent`, and `ssh-keyscan`; any later binary install removes old loadout-owned `~/.local/bin/{ssh,scp,sftp}` by exact hash.
- **AutoHotkey reads its feature config at runtime, not at install time.** `envs/autohotkey/hotkeys.ahk` parses `%USERPROFILE%\loadout_keys.toml` at startup to compute `cfg_feature_*` (reusing the in-script partial TOML parser: `loadout_toml_read_quoted_array` for the `enabled = [...]` array, plus `loadout_toml_read_bool` for `[autohotkey].enabled`). The installer (`loadout.ps1`) no longer stamps booleans into the copied script -- editing the toml and reloading (`Ctrl+Alt+R`) is enough; no reinstall needed. Defaults apply only to undefined settings (`[autohotkey].enabled` default true; every optional feature default off, matching prior installer behavior). Legacy `[autohotkey.plugins]` arrays and numeric-prefixed/underscored ids are mapped onto current ids at startup. Override the config path with the `LOADOUT_KEYS_TOML` env var (used by `envs/autohotkey/test-run.ps1`, which now writes a sandbox toml instead of regex-patching flags); run `AutoHotkey64.exe hotkeys.ahk --print-config` to dump the resolved config and exit before any hotkey registers. Set `[autohotkey].logging = true` for timestamped runtime diagnostics in `<scriptdir>\hotkeys.log` via the gated `loadout_log` helper (SSID source netsh vs event-log, VPN Wi-Fi skip decision, Cisco auto-login actions/errors) -- off by default, wrapped in `try` so it can never disrupt hotkeys. AHK v2 gotchas: functions reading script-globals must declare `global`; `&&` yields 1/0 so `#HotIf cfg_feature_x` works directly.
- The mate-terminal shanghai bundle must include both `org.mate.terminal.gschema.xml` and `org.mate.interface.gschema.xml`, then compile schemas at install time. The binary reads `org.mate.interface/monospace-font-name` during startup; without that schema it aborts with `Settings schema 'org.mate.interface' is not installed` before opening. Keep the minimal interface schema source at `build/mate-terminal/org.mate.interface.gschema.xml` and copy it into the archive when rebuilding.
