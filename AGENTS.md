## Cold Start

engineering-loadout = offline-first, no-root package manager for Linux compute environments. Multi-platform Linux (RHEL 7/8/9, Suse, x86_64/ARM/PowerPC), offline (all deps bundled), multi-org layer hierarchy (global/corp/site/team/project/user). Installs Bash, Vim/Neovim, Tmux, Helix, Starship, 100+ prebuilt CLI binaries, GUI lib bundles, runtime archives, fonts, data caches. 100% Linux-only: Windows/macOS support retired 2026-08-31, offloaded to the windows-dotfiles repo (macos may be revisited someday; windows will not).

Default install root (the shared tree) is `$XDG_DATA_HOME/loadout` (`~/.local/share/loadout`); per-user config, caches and nvim data always stay under the real `$HOME` (two-root model). Persistent config lives at `~/.config/engineering-loadout/config.toml` (`dest_dir`, `prefer`, `prefer_off`).

`./loadout` = POSIX-sh shim (~80 lines): resolves Python 3.14 via (1) an installed `<prefix>/bin/python3.14` (portable-python; `<prefix>` = install root) → (2) `<repo>/.loadout-bootstrap/bin/python3.14` warm cache → (3) cold bootstrap: decompress `payload/<platform>/portable-python-*.tar.bz2` into `.loadout-bootstrap/` (needs only bzip2+tar; gitignored, per-clone). Then execs `loadout_main.py`. No system Python required. Installer enforces >=3.14 (`sys.version_info` gate; uses PEP 758 syntax older parsers reject). **PEP 758 — do not "fix" the bare `except A, B:` form:** it is valid on 3.14 and means exactly `except (A, B):` (Py2's catch-A-bind-B semantics were NOT reintroduced). Parentheses are REQUIRED with `as` — `except (A, B) as e:`; the bare form there is `SyntaxError: multiple exception types must be parenthesized when using 'as'`. `ruff format` (`target-version = "py314"`) strips the parentheses, so re-adding them is churn; a pre-3.14 interpreter or analyzer rejects the whole file with the stale "multiple exception types must be parenthesized" message — never run one over `loadout_main.py`, and never rewrite a handler because of it. Shim resolves repo from script path; works from any cwd.

Gates: `sh -n loadout`; `python3 -m py_compile loadout_main.py`; `bash -n envs/bash/global/bashrc`; first-party Python stays ruff-formatted (`ruff format --check --force-exclude`, T1; py314 so multi-except parens are stripped); headless nvim needs temp state dirs: `XDG_CACHE_HOME=/tmp/codex-nvim-cache XDG_STATE_HOME=/tmp/codex-nvim-state nvim --headless +qa`.

## Build Machine Mandate

Dev platform moved 2026-09-01: AlmaLinux 8.10 WSL2 → CachyOS (Arch-family, glibc 2.44, kernel 6.x). The EL8 build machine is now the **`loadout-build` docker container** (`build/Dockerfile`, base `almalinux:8.10`, glibc 2.28, base gcc 8.5.0 + gcc-toolset-14 at `/opt/rh/gcc-toolset-14/enable`). Enter via `build/build-shell [cmd]` (bind-mounts repo at `/repo`, runs as invoking uid).

Rules:
- ALL compiling/packaging/payload-mutating work happens in the container, never on the native host. Two reasons: (1) glibc floor 2.28 is a link-time property — only EL8 userland guarantees it; cross-compiling FROM CachyOS is forbidden (configure/run probes execute target binaries and would probe the host: kernel 6.x, glibc 2.44 — the build-box-masking bug class); (2) byte reproducibility — CachyOS bzip2 1.0.8 does not round-trip EL8's 1.0.6 bytes (confirmed: a native strip-all-elf-binaries run churned 29 unrelated payload archives).
- GRAND PLATFORM IMAGE: `loadout-build` is the EL8 build PLATFORM, not a thin dnf layer. End state — every supported target's build runs with ZERO dynamic installs. Incremental rule: each time a target is rebuilt, absorb whatever boilerplate its build script had to `dnf install` on the fly into `build/Dockerfile` in the same change, so the next rebuild finds it preinstalled. Never leave a build-*.sh whose real-world flow still shells out to dnf mid-build. Build-time toolchain/devel closure belongs in the image; runtime deps of built artifacts stay out. First sweep done 2026-09-01: all prerequisite lists from build-*.sh headers (Qt5 -devel set incl. qttools/qtxmlpatterns, libaio/readline/fftw/tcl/ruby-devel, help2man, autoconf-archive) are baked. No build script executes dnf install — headers document prereqs only; keep it that way.
- Image bakes what EL8 gets wrong out of the box: **cmake = Kitware 4.4.3 binary tarball** (dnf's 3.26 has the nvim-blocking bug class; building cmake from source wastes ~30 min per image rebuild), **ninja-build**, gettext-devel, perl-IPC-Cmd/Time-Piece (CPython configure needs them), plus the full X11/GUI devel closure + *-source repos for `dnf download --source`. Bump cmake via the `CMAKE_VERSION` ARG in `build/Dockerfile`.
- `--network=none` is a TEST-time rule (Tier 3 + automated docker runs), NOT build-time. Image builds and dnf inside the container may use the network.
- LLVM 23 toolchain (clang-23, llvm-{ar,ranlib,profdata,bolt}, lld, merge-fdata; required by portable-python's PGO/LTO/BOLT build) lives at `~/.local/bin` on the host. It was built against an old loader floor (interpreter `Linux 3.2.0`) and RUNS INSIDE the container: bind-mount `~/.local` (ro) or copy the tools in. Verified working. Alternative: `docs/BUILD_LLVM_EL8.md` documents building LLVM in an EL8 userland.
- Everyday dev (shell configs, installer testing, day-to-day loadout use, T1/T2 tests) runs natively on CachyOS — the native/foreign-platform gap is the point of running loadout on a non-EL8 box. Install-behavior/payload/repo-layout changes still need the Tier 3 container gate (`tests/prebuilt-binaries-almalinux8 --full`, `--network=none`) before trusted.
- Dev-host scratch: CachyOS `/tmp` is a 16 GB tmpfs — NEVER point dev-side work predicted to exceed 12 GB at it (full `@shared` dest installs ≈8 GB installed plus extraction transients; PGO profile writes filled it before). Use disk-backed scratch (`/var/tmp`, same filesystem as `$HOME`) via `TMPDIR` for release runs, manual `@shared` installs, and build workdirs. Failure mode is silent ENOSPC mid-extraction: phases WARN-and-skip, and the missing files surface later as FLAKY, run-varying test failures. This rule is dev-side only — end-user install temp behavior is unchanged.
- FORWARD COMPATIBILITY: EL8 is the MINIMUM, never the ceiling — loadout must run on any newer Linux. Mechanisms (enforce on every new/bumped package): glibc floor is link-time only (NEVER bundle glibc/GL dispatchers/libstdc++ — host always supplies); bundle ONLY sonames the host can't supply, host copy wins for everything else (libssl/libcrypto.so.1.1, libcrypt.so.1, firefox's libffi.so.6/libjpeg.so.62 — carried as unclaimed lib64 stems or co-located in the archive); keep wrapper loader paths strictly inside the bundle (never `$prefix/lib64` — EL8-era gui_libs shadowing newer host stacks is the shipped-bug class); never bundle distro-specific trust proxies (nssckbi); GUI wrappers probe host GL/fontconfig and export nothing when the host provides them. Gate pair enforces both sides: Tier 3 container proves the floor, native T1/T2 on the newer dev host probe the ceiling — the 2026-08-30/31 firefox/wezterm batches were the ceiling gate catching floor-green payloads. Known gap (future work): NEEDED-closure audit is per-package hand-rolled guards; a repo-wide auditor classifying every shipped ELF's NEEDED sonames (bundled / unclaimed-stem / assumed-host-present) does not exist yet.
- Historical note: pre-2026-09-01 payloads were built on AlmaLinux 8.10 WSL2. BUILD.md files embedded in old artifacts (portable-python, etc.) still reference that box; treat those paths as recipe documentation, not the current machine.

## Registry & Resolver

`payload/packages.json` schema_version 3: every installable = named entry with `kind` ∈ {bin, lib-bundle, runtime, typelib, python-base, python-tool, env, font, data, group}, `platforms:[...]` ('linux' sole value; windows/macos retired 2026-08-31), optional tags/version/version_url/version_pattern/version_scheme/auto_update_interval/pin_reason/optional:true/rolling_git, hard `depends`, soft `recommends`, registry `prefer:[tool,...]` (env packages: tools the bundled build should win over the system copy), per-kind artifact fields (bins/libs/wheels/archive/source/members/install_to/sentinel...). Groups = keys starting `@`, recursive expansion w/ cycle detection.

Synthetic groups expand at runtime (in `_SYNTHETIC_GROUPS`, surface in list --groups/describe):

| group | members |
|---|---|
| @shared | all non-group non-optional kind!=env |
| @shared-all | same + optionals |
| @envs | env-bash + env-tcsh (+env-bash's recommends) |
| @envs-all | every kind==env incl optionals |
| @all | literally everything (@shared-all + @envs-all) |

Bare `all` raises ResolverError (historic semantics were inverted; use `@all`). NO "@all minus caches" variant exists or should: caches (nvim-plugin-stash, treesitter-parsers, tldr-data ≈19% payload) ARE the product; dropping them drifts against upstream. `optional:true` is the ONLY gating field (no `default`); flagged pkgs install only when named explicitly / via `-all` group / via listing group members (surfer=name-only; env-tcsh via name/@envs/@envs-all).

Resolver order: parse --skip (groups expanded) → initial set from positionals → subtract skip → walk_depends (raise on dep∈skip unless --no-deps/--force) → walk_recommends (silent drop of skipped/unknown) → filter_by_platform. Tools/env bundles fully decoupled (no cross-recommends): `@shared --dest-dir X` and `@envs` are independent stages.

The former curated mega-group is retired: `_RETIRED_GROUPS` makes the resolver raise a loud error naming the replacements -- `@shared-all` (bundled tools) then `@envs-all` (per-user shell/editor configs). Their union is a strict superset of the old group (177 vs 167 resolved names).

Selection flags: positionals; `--skip NAMES`; `--no-deps` verbatim set; `--force` warn-and-continue past resolver errors; `--dry-run`; `-y|--assumeyes|--yes`; `--allow-online-plugin-sync` (default offline stash path); `--no-verify` (skip sha256 vs .content-manifest); `--install-follows-symlinks yes|no|auto` (auto=follows only when target writable). Bare loadout / bare install → usage + nonzero exit. `-V` prints git-describe/release stamp.

Transaction summary: dnf-style `[Y/n]` (capital = bare ENTER). Sizes are INSTALLED (uncompressed) bytes from precomputed `payload/installed-sizes.json` (`build/gen-installed-sizes`; bzip2 stores no length). Map keyed PER FILE not per pkg (wheels shared across tools; union then size once; overshoot prints note). Chunked artifacts collapse to logical name before lookup. bin/*.bz2 counted whenever file exists (gtkwave has bins AND share-archive; doctor's carve-out under-reported 10x). File `source` counted directly (os.walk on a file yields nothing — a file-valued source would size as 0 B); a directory source counts its whole tree (env-starship ships `envs/starship/`, so its schema rides along). Map missing → fallback to compressed size announced loudly. **Non-TTY stdin ABORTS exit 1** ("pipe is not consent"); all automation passes -y — add -y to any new automation.

## Install Pipeline

Phases receive selected_tools, short-circuit when their pkgs not selected. Order: backup → pre-built binaries → config files (silent) → prefer shims (silent) → fonts → tldr cache → portable Python → GObject typelibs → Python tools → runtimes (Vim/mate-terminal silent...) → nvim stash/bundle/Tree-sitter (silent) → headless Lazy sync → post-install hooks → layer install.sh → compress backup. Phase→root routing: backup/config + per-user nvim bundle/Lazy/state go to `env_home` (the real `$HOME`, or the staged root for env-only + explicit `--dest-dir`); pre-built binaries, tldr cache, portable Python, typelibs, Python tools, runtime archives, vim runtime, nvim-qt, treesitter vendor, plugin stash and tree-sitter parsers go to `install_root`. Fonts go to `env_home` when the install root is the real `$HOME` (or lives inside it, e.g. the config `dest_dir`), and otherwise ONCE into `install_root` (`<prefix>/share/fonts`) plus a generated `<prefix>/etc/fonts/loadout-fonts.conf` the shells export `FONTCONFIG_FILE` for — fonts are identical for every user of a tree and ~2 GB per home is exactly what a quota'd cluster account cannot pay. Env-only selection writes only ~/.config + rc text (prebuilt skips entirely when no bins/libs selected, incl base libs). nvim phases split: plugin_bundle+headless Lazy sync run when a loadout nvim binary plus env-nvim config are present (including split shared-prefix installs); treesitter_vendor/parsers gate on treesitter-parsers; plugin_stash gates on nvim-plugin-stash. @shared dest-dir installs stash+parsers but seeds no lazy/ and does not run Lazy without per-user env-nvim; per-user env stage seeds lazy/ then runs `nvim --headless -n '+Lazy! sync' '+qa'` against the local/shared stash.

prefer shims: after config files, `install_prefer_shims()` reconciles `<prefix>/prefer/<tool>` exec shims. Active set = registry `prefer` defaults of installed env packages + config `prefer` − config `prefer_off` (env-tmux declares tmux). Shims carry `PREFER_SHIM_MARKER`; only marker-carrying files are pruned/overwritten, foreign files warn and stay, missing targets warn and create nothing, read-only root warns and continues.

Writability pre-check per area; refuse area w/ warning, continue later areas; results table done/FAILED (SKIP omitted; silent areas hidden unless FAIL) + `Complete.`/`Completed with N problem(s)` + Processes Blocking Installation table (ETXTBSY) + --no-backup data-loss warning. Intended-permissions rule: installer owns its tree's modes — every installed file/dir gets owner-write (+x for dirs) regardless of source modes or user hardening (`_grant_owner_write`; bins already explicit 755/644 via `write_bz2_atomic`); the writability gate heals owner RO dirs instead of refusing, refuses only when healing fails (foreign owner, RO mount) — reinstall-over-`chmod -R a-w` stays idempotent. Single-package selection: row re-labeled w/ package name, header `Package`, phase→Detail (_RESULT_PKG_LABELS; keep multi-pkg output coarse/Area).

--dest-dir: per-verb on install/reinstall/upgrade + snapshot subcommands; read-only verbs reject. Resolution order: explicit flag > config.toml `dest_dir` > `$XDG_DATA_HOME/loadout` (fallback `~/.local/share/loadout`). `_local_root(home)` keeps `.local` only for a real-$HOME root; every other root is a plain prefix (`<root>/bin`, `<root>/share`; the old un-dotted `<root>/local/` level is GONE). `_resolve_install_to()` drops a leading `.local` component outside HOME mode and applies to hardcoded joins AND packages.json install_to. Tree stays relocatable (RPATH $ORIGIN, launcher-derived prefixes, venv dirs inside the prefix) — no post-install rename. Two roots: config/cache/per-user nvim data always under the real `$HOME` (mixed selections never drag config into a dest tree; env-only + explicit flag stages a whole HOME; env-only + config `dest_dir` ignores it with a printed note). Snapshot targets the real `$HOME` unless `--dest-dir` was typed on the command line; config `dest_dir` does not move snapshots.

Backup: numbered `loadout_backups/backup.N/` (starts .1; never bare), skips repo-pointing symlinks, never overwrites; compressed to backup.N.tar.bz2 at end, dir removed; numbering checks both forms; hooks (get LOADOUT_BACKUP_DIR) run before compression; excludes font extensions; fonts phase does its own fonts.bak* move (suppressed by --no-backup → reuse dir in place). snapshot restore accepts dir or archive (extracts under current temp root, restores).

Post-install hooks: executable w/ own shebang, direct exec, fail installer on failure, run after global steps before layer install.sh, env: LOADOUT_REPO/HOME/BACKUP_DIR/DEST_DIR/NO_BACKUP. Paths resolved before chdir $HOME.

Interrupt handling: ^C during backup phase kills writer subprocess, removes partial backup dir, exits 130. Otherwise graceful: finish current step, print results, exit 130; double ^C force.

Atomicity: all bz2 decompression via write_bz2_atomic (same-dir temp + os.rename) — prevents SIGBUS when running process has lib mmap'd. Blocked binaries (ETXTBSY after retry) staged to `${TMPDIR:-/tmp}/loadout-pending-<user>/files` + pending-daemon spawned (applies when proc_exe_absent clears; 1-week timeout from last_activity; pidfile-guarded single instance). pending.json entries carry src_bz2+src_sha256; merge prunes entries whose staged file/source vanished or hash changed (never apply outdated binary; entries without src_bz2 left untouched). Daemon pidfile-check+spawn under _pending_lock (no two-daemon race). Internal temp-root temps MUST be dot-hidden (`.loadout-*`): `clean --all` sweeps `loadout-*` only under the current temp root, so bare prefixes can let concurrent clean corrupt mid-extraction install. Never hardcode scratch `dir="/tmp"`; honor TMPDIR unless a protocol requires `/tmp` (e.g. X11 sockets).

Content verification: `_verify_source_files` hard-errors on payload file missing from .content-manifest (strict allowlist). `.content-manifest.fetched` extends allowlist for fetched release assets; only tools/fetch-stash may add entries, only after sha256 match vs published sums (mismatched file deleted, never left).

.content-manifest covers the SHIPPED set — what `git archive HEAD` puts in a release tarball — not the release host's directory. Generation skips untracked+ignored files (`git ls-files -o -i --exclude-standard`: any depth, plus .git/info/exclude and core.excludesFile), so a vendored plugin's `.agents/.codex/.claude` trees cannot leak in; `--check` reports a present-but-unshipped entry as NOT-SHIPPED; `build/verify-manifest-export` proves HEAD's manifest against HEAD's archive. A manifest entry for a gitignored host file verifies on that host and is MISSING in every clean clone — the 2026-10-07 export blocker (158 entries under tmux-persist). Stash exception unchanged: it is a release asset, absent from both export and manifest.

Trust chain (do not shortcut): signed tag → sha256sums.txt (release asset) → stash bytes → .content-manifest.fetched.

## Package Behavior Reference

### Prebuilt binaries
Platform dir select: exact ABI names preferred (`el8.x86_64.glibc2p28`); fallback compatible same-arch glibc ≤ host. bin/*.bz2→`<prefix>/bin` exec; lib64/*.bz2→`<prefix>/lib64` (install root; default `~/.local/share/loadout`, `~/.local` only in legacy HOME mode). RPATH `$ORIGIN/../lib64:$ORIGIN/../lib` pre-baked in repo (repatch-binaries) — installer = decompress+chmod only. ldd check runs ONCE at end of full install (not per-phase: zsh needs libzsh from later runtime phase; early ldd false-warned). Running binary can't be replaced → continue + retry notice/stage pending. Subprocess calls use absolute paths (_LDD/_UNAME/_GETCONF via _find_tool) so installed binaries never shadow host tools.

NEVER bundle: glibc components (libc/libm/libpthread/libdl/librt — must match system ld-linux exactly; GLIBC_PRIVATE crashes); OpenGL dispatchers (libGL.so.1/libGLX.so.0/libGLdispatch.so.0 — display-driver-linked; Mesa vendor side OK: mesa3d_libs ships libEGL_mesa/libgbm/libglapi/DRI/GLVND JSON/libLLVM-17, wrappers must set LD_LIBRARY_PATH+LIBGL_DRIVERS_PATH+__EGL_VENDOR_LIBRARY_DIRS); C++ runtime (libstdc++/libgcc_s — subtle mismatches; exceptions: verilator static-links them; surfer NEEDs only glibc+libgcc_s).

Bundling order CRITICAL: strip → patchelf(RPATH) → bzip2. PROMPT BLOCK IS CLOBBER-SENSITIVE — do not simplify back to owning PROMPT_COMMAND. Facts: loadout doesn't own PROMPT_COMMAND; starship init self-hooks (registers into precmd_functions ARRAY when framework live — bash-preexec/ble.sh — else PROMPT_COMMAND). Login shells often already have bash-preexec live (/etc/profile.d/wezterm.sh+vte.sh register precmd_functions+PROMPT_COMMAND stub BEFORE our bashrc); our unset -f deletes framework fns leaving dangling refs. Required fixed order: (1) reset framework state (unset precmd_functions preexec_functions __bp_imported bash_preexec_imported PROMPT_COMMAND) → (2) source loadout-owned wezterm.sh (re-installs working bash-preexec+wezterm hooks from user space; serves raw wezterm + tmux-in-wezterm; off-WezTerm shells get skip-vars so no raw OSC/no set-working-directory stalls) → (3) eval "$(starship init bash)" letting it self-hook — NEVER unset/overwrite PROMPT_COMMAND around it → (4) loadout_add_precmd loadout_restore_echo. Symptom of regression: Starship absent on first login shell, fine after exec bash (non-login never sourced /etc/profile → no framework → falls back PROMPT_COMMAND). VERIFY VIA REAL PTY (tmux send-keys), never bash -lic (no prompt cycle hides bug); test login AND exec bash.

WezTerm integration: loadout-owned vendored envs/bash/global/wezterm/wezterm.sh (PROVENANCE header; runtime archive ships binaries+completion only, NOT integration). Resolution: explicit var → vendored → relative to installed wezterm → shared prefix; never /etc/profile.d. Default on; self-skips dumb/linux/non-interactive. tmux-in-wezterm needs allow-passthrough on. ## Workflow Patterns

Stable-release policy: bundled tools from stable tagged releases only — never HEAD/nightly/dev builds (nvim 0.13-dev, micro -dev rejected). build/build-*.sh enforce --tag. Exception: first-party rolling-git projects (above). Some tools have no EL8-compatible official prebuilt (nvim official needs GLIBC_2.34) → source-build stable tag on EL8. Provenance: build/verify-binaries [pkgs]; EL8 source builds/patchelf deltas documented in _SKIP_REASONS.

Add binary MANDATORY: build notes in build/ADDING_BINARIES.md BEFORE committing — complete enough to reproduce w/o re-derivation: name+version, prereqs, REAL flags used, patches (before/after if nontrivial), packaging steps (strip→patchelf→bzip2 exact commands), quirks. Payload regen chain ORDER MATTERS: bzip2 → cp into payload/{bin,lib64} → ./build/strip-all-elf-binaries → python3.14 build/gen-installed-sizes (BEFORE manifest — sizes file lives under payload/, manifest hashes it; reversed order = stale manifest) → python3.14 build/gen-content-manifest → git add payload/ .strip-manifest .content-manifest → commit (pre-commit re-strips/re-records). Both have --check wired to Tier 1. gen-content-manifest deliberately keeps untracked-not-ignored files (the chain regenerates before `git add`), so commit the payload file in the same change; build/verify-manifest-export (Tier 1, build/export preflight, release Step 3b) refuses a committed manifest that covers a file git does not ship. Shared libs → lib64/*.bz2 (raw ELF there never installed). Add farm-versions TOOLS entry w/ strategy. Regenerate completion after registry change.

Version currency: build/check-versions [--outdated-only|--include-na|--format tsv|json|--offline] — GitHub releases/tags API + PyPI JSON; GITHUB_TOKEN/GH_TOKEN for 5000/hr. Reports only, never throttles; deliberately-pinned pkgs carry pin_reason surfaced in table (hx = permanent mismatch by design — do NOT "fix"). Update cadence: auto_update_interval on pkg (default 6mo; <N>d/w/mo/y|never; declarative, reviewable next to pin_reason; dev artifacts take it on AUTOMATED entries). State in build/currency-state.json (NOT registry — manifest hashes packages.json; build/ export-ignored). Bare ./build/update sweeps DUE only; named pkg always updates (still stamps date); --ignore-cadence forces; --currency table. EVERY failure mode FAILS OPEN (bad interval/corrupt timestamp/unreadable state → warn + treat as due; silent-freeze is the unacceptable failure). Boundaries pinned by tests/update-cadence.

Release: follow docs/RELEASE.md (authoritative ordered procedure: release class, auth-at-kickoff, currency sweep, security refresh, mandatory post-payload chain, assurance re-pin, doc sync, gates by class, post-publish verification, catalogue of shipped mistakes). ./build/release runs gates only — cannot detect earlier skipped steps. Gates in parallel: scan-for-malware, tests/prebuilt-binaries, farm-versions tsv, sha256sums+SBOM generation, manifest export (HEAD:.content-manifest vs `git archive HEAD`), secret-scan (tree+history), vuln-scan (wheelhouse baseline-gated); tag/publish waits, blocked on scan/smoke/checksum/manifest-export/secret/vuln failure. scan caches CLEAN verdicts only (~/.cache/engineering-loadout/malware-scan-v1/; key hashes corpus+script+YARA binary/rules/tag+flags+ClamAV fingerprint; --no-cache/--clear-cache). Binary smoke: @shared --dest-dir, probes every `<dest>/bin` exec with PATH restricted to dest+system (wrappers can't cheat via the host's ~/.local/bin); checks loader failures/signals/editor sentinels/headless nvim vs installed runtime. Pass-condition = EXIT 0; any nonzero needs EXPECT_NONZERO entry (old {126,127,139}-excepted rule scored 42/300 green wrongly). Host-contract skips explicit: cloc(perl), meld(python3.6), GL GUI(host GLVND), firefox/idle3(capabilities: userns/tk — probed via HOST_REQUIRED_CAPABILITIES, must exit 0 on capable hosts). Stash asset reuse on re-release: byte-match (size+sha256 in previous sha256sums.txt) + signed tag → undraft release, move tag, clobber small assets only; re-reads release asserting published+stash present, full-upload fallback.
